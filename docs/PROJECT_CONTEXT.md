# 项目上下文摘要

更新时间：2026-10-06。根据本地 main 对话记录和当前代码整理，供后续开发直接接续。

## 目标与既有约定

- dfAmmo 是 Windows 上的三角洲行动 / WeGame 自动化桌面工具。用户认为整体流程约完成 2/3，后续以已有功能的稳定性和流程补完为主。
- `main.py` 负责启动、DPI 和 UAC；`scripts/` 按功能拆分模块，GUI、识别、输入、导航和文件操作分别维护。
- 通过按住绑定按钮、拖到 WeGame 窗口并松开绑定。保留实时窗口坐标、物理像素与高 DPI 兼容；避免依赖固定桌面坐标。
- 支持框选采集 / 覆盖模板。历史对话讨论过 Airtest，但当前运行中的匹配引擎是 OpenCV `matchTemplate`，不能将安装了 Airtest 等同于使用了它。
- GUI 保留清晰的步骤跟踪、单步 / 连续模式、底部独立日志区和安装目录输入；此前用户要求删除无用测试占位按钮。
- 已运行的游戏可直接接管导航；否则识别 WeGame 启动按钮并等待游戏进程。
- 导航：选择烽火地带 → 空格关闭活动弹窗 / Tab 进大厅 → 打开地图 → 长弓溪谷 → 开始行动 → 确认配装 → 确认继续 → 出发 → 检测选人界面。
- 当前代码在选人界面完成后核对进程身份并终止游戏；确认退出后再执行安装目录下 `DeltaForce/PackContent/Paks` 的 Pak 重命名及 WeGame 后处理。
- 两个目标 Pak 文件由配置指定，使用 `.disabled` 后缀并支持恢复。阶段 3 为等待启动按钮、更多选项、资源包管理、删除长弓溪谷资源、重新启动游戏。
- `start.bat` 使用 uv 和锁文件准备环境；`.venv` 不应被当作跨机器可直接搬运的运行包。

## 本次问题与修复

用户反馈强行停止快捷键失效、切换单步 / 连续卡顿，并要求审阅和优化项目。

根因是主线程同步执行截图匹配、等待、键鼠序列和最长数十秒的后处理循环；`processEvents()` 造成重入，不能提供可靠停止。另有暂停按钮调用不存在的 `toggle_navigation_pause()`，Shift+F12 未单独注册，以及长按 F12 每 350ms 反复触发。

- `task_runner.py`：单后台线程执行耗时服务，GUI 线程运行编排与更新控件；同一时间只有一条任务链，不积压定时器请求。停止关闭任务链，并保留后台占用状态直到旧操作结束，防止旧结果续跑和新旧任务重叠。
- `task_control.py`：共享停止 / 暂停信号，等待可中断；识别前后及输入、文件修改前检查。键鼠按下后通过 `finally` 保证抬起，中断不会触发备用点击。
- `gui.py`：分别注册 F12（暂停 / 继续）与 Shift+F12（停止），使用 MOD_NOREPEAT；注册失败时仅由按键检测备用路径处理，每次按下只触发一次。关闭窗口时注销快捷键并取消后台任务。
- `gui_actions.py`：启动、进程检查、导航、单步及连续后处理交给任务链；移除业务代码中的嵌套事件处理。进度样式仅在变化时刷新，日志批量追加。
- `element_locator.py`：候选匹配共用截图，模板缓存按文件时间 / 大小失效，支持中文路径。
- `game_navigation.py`：刷新窗口位置并处理识别后窗口移动；初次重同步透传完成 / 暂停状态。
- `game_process.py`：先检查进程名，只读取匹配进程的路径和启动时间。
- `window_binding.py`：保留工作区已有的输入线程附加逻辑，补上异常时的 `finally` 解除附加。

## 验证与边界

使用项目 `.venv` 运行 `python -m unittest discover -s tests -v`。覆盖 GUI 布局、Pak 临时文件操作、模式识别，以及界面响应、停止、暂停、快捷键路由和缓存刷新。新增响应性测试中的游戏 / Win32 操作均为替身。

已通过离屏 GUI 初始化与关闭检查、源码编译检查。没有执行真实游戏终止、真实资源包删除或重启。实际游戏环境中的全局快捷键接收、权限 / 前台激活及完整流程仍需现场验证。

停止属于协作中断：正在执行的单次 OpenCV 或系统调用需要先返回，但其结果会被丢弃，后续自动化不会继续。已经完成的点击、进程终止或文件修改不会被撤销。
