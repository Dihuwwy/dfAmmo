# dfAmmo

面向 Windows 的《三角洲行动》半自动卡邮件助手，提供视觉模板识别、窗口绑定、分阶段执行和运行日志。

半自动流程在进入仓库并确认提示后结束，后续穿戴装备、等待地图恢复、切换模式和重连由用户完成。

> 当前支持半自动模式，全自动模式尚在开发。游戏或 WeGame 更新、分辨率或缩放设置变化后，可能需要重新采集模板。

## 功能与状态

- 拖拽绑定 WeGame 主窗口，检测游戏进程并接管导航。
- 通过图像识别定位界面元素，模拟键鼠完成操作。
- 提供单步、阶段、连续三种执行方式，以及步骤状态和底部日志。
- 支持导航暂停、继续、停止和画面重同步。
- 提供 Pak 文件屏蔽与恢复操作，在发送 WeGame 删除操作前检查屏蔽状态。
- 内置框选截图工具，用于更新识别模板。

### 半自动流程

| 阶段 | 内容 |
| --- | --- |
| 阶段一：游戏内自动导航 | 启动或接管游戏，进入烽火地带大厅，选择长弓溪谷并出发；识别到选人界面后终止游戏进程 |
| 阶段二：隔离 Pak 补丁文件 | 将配置的地图 Pak 文件重命名为带有 `.disabled` 后缀的文件 |
| 阶段三：WeGame 修复重置与拉起 | 返回 WeGame，打开资源包管理器，操作长弓溪谷资源条目、确认并关闭管理器，再启动游戏 |
| 阶段四：重返大厅与恢复地图 | 先恢复 Pak，再处理提示并进入大厅、发送地图下载请求，最后进入仓库并确认提示 |

**半自动模式只执行一次，不循环。** 发送地图下载请求不代表地图已恢复完毕；请等待游戏完成校验或下载后再进行后续手动操作。

### 全自动模式

全自动模式尚在开发，自动配装、重连和循环功能暂不可用。当前请使用半自动模式。

## 环境要求

- Windows 10 / 11，64 位系统。
- 已安装 WeGame 和《三角洲行动》，且能够手动启动游戏。
- 运行期间保持桌面未锁定，目标界面可见且未被遮挡。
- 管理员权限：程序启动时会检查权限，必要时通过标准 UAC 确认框请求授权。

目前仅支持 Windows。

## 快速开始

### Windows 便携版本

在 [Releases](https://github.com/Dihuwwy/dfAmmo/releases) 下载 Windows x64 ZIP 包，将整个文件夹解压到可写目录，再双击 `dfAmmo.exe`。此方式无需安装 Python 或 uv。

不要只复制 EXE：需要保留 `_internal/`、`assets/` 和许可文件。包内不包含个人配置，首次启动会在 EXE 旁生成 `config.json`。程序未签名，系统可能显示发布者未知；请核对下载来源与 `.sha256` 校验文件，不要关闭安全软件。

### 从源码运行

需要 Python 3.11 或以上，推荐 Python 3.11，并使用 `uv` 管理依赖。下载仓库源码，或克隆：

```powershell
git clone https://github.com/Dihuwwy/dfAmmo.git
cd dfAmmo
uv sync --frozen --python 3.11
uv run --frozen main.py
```

也可以双击根目录的 [start.bat](start.bat)：

- 检测到 `uv` 时，先执行 `uv sync --frozen`，再启动程序。
- 未检测到 `uv` 时，尝试使用项目内已有的 `.venv`。
- 没有可用环境或依赖同步失败时，会显示错误并退出。

首次同步需要下载依赖，耗时取决于网络和环境。更换电脑时，请重新创建运行环境，不要直接复制已有的 `.venv`。

## 使用方式

1. 打开 WeGame，进入《三角洲行动》的游戏页面。
2. 启动 dfAmmo，在系统 UAC 提示中确认授权。
3. 填写游戏安装目录，应选择包含 `DeltaForce` 子目录的目录。程序据此定位 `DeltaForce/PackContent/Paks`。
4. 按住窗口绑定按钮，拖到 WeGame 主窗口后释放。
5. 选择半自动运行模式，以及所需的执行方式。执行方式默认是连续。
6. 确认游戏装备与地图准入条件，然后点击“开始卡邮件”。游戏已运行时，也可以使用“接管导航”。
7. 查看底部运行日志。半自动完成后，手动处理装备、地图恢复等待和重连。

### 执行控制

| 控制 | 行为 |
| --- | --- |
| 单步 | 完成一个动作后暂停或停止推进，便于检查结果 |
| 阶段 | 完成当前阶段后停止，不自动衔接下一阶段 |
| 连续 | 自动衔接已实现的后续阶段；不等同于循环 |
| `F12` / 暂停按钮 | 暂停或继续游戏导航；并非所有后处理阶段都支持暂停 |
| `Shift+F12` / 停止按钮 | 请求停止当前自动化任务 |
| 重同步 | 重新识别当前游戏画面并对齐导航进度 |
| 接管导航 | 检测运行中的游戏并尝试对齐当前步骤 |

点击停止后，当前操作可能需要短暂时间才能结束。停止不会撤销已完成的操作，也不会自动恢复 Pak；中途停止后请检查 Pak 状态，必要时使用恢复操作。

## 配置

首次启动会自动生成 `config.json`，用于保存个人设置。EXE 版将配置保存在可执行文件所在目录；游戏目录和运行模式可以直接在界面中设置。

主要配置项如下，完整字段与默认值见 [scripts/config.py](scripts/config.py)：

| 字段 | 默认值 / 说明 |
| --- | --- |
| `game_install_dir` | 空字符串；填写包含 `DeltaForce` 子目录的安装目录 |
| `operation_mode` | `semi_auto`；另有 `full_auto`，其后续功能尚未实现 |
| `template_match_threshold` | `0.78`；部分专用识别使用单独阈值 |
| `game_process_names` | 游戏进程名候选列表 |
| `game_process_timeout_seconds` | `120`；等待游戏进程的超时时间 |
| `navigation_step_timeout_seconds` | `60`；导航步骤的超时时间 |
| `pak_file_names` | 需要屏蔽或恢复的 Pak 文件名列表 |
| `game_confirm_template` | `df_confirm.png`；部分游戏提示共用的绿色确认模板 |
| `wegame_confirm_delete_template` | `wegame_confirmdelete.png`；完整的 WeGame 删除确认弹窗 |

手动修改配置前请退出程序。

## 模板采集

模板位于 [assets/templates](assets/templates)。遇到界面更新或识别不准确时，可通过内置截图工具更新模板。

1. 暂停或停止任务，将目标界面放在前台。
2. 点击“采集模板”，输入模板名称，不包含 `.png` 后缀。
3. 拖拽框选目标区域，释放后保存；按 `Esc` 取消。
4. 使用相同名称可覆盖旧模板，请提前备份。

选择稳定且有辨识度的区域，避免包含倒计时、用户名、文件大小、地图容量等动态内容。当前采集遮罩以主显示器为范围，建议在主显示器上完成采集和初次验证。

特别注意：

- `wegame_confirmdelete.png` 必须包含完整删除确认弹窗，不能只截确定按钮或文字。
- `wegame_bin.png` 是悬停资源条目后显示的垃圾桶图标。
- `wegame_assets_manage.png` 对应菜单项；`wegame_assests_manage.png` 对应管理器顶部区域，请按原文件名分别采集。
- `df_confirm.png` 用于部分游戏提示的绿色确认；配装确认、继续和 WeGame 橙色确定仍使用各自的模板。

    └── styles.py            # 界面样式

## 故障排查

| 问题 | 建议 |
| --- | --- |
| 模板识别超时或点击偏移 | 检查模板、分辨率、系统缩放、窗口状态和遮挡；必要时重新采集，不要仅降低阈值 |
| 鼠标不移动或输入无效 | 确认管理员授权、目标窗口焦点和交互桌面状态，查看具体错误日志 |
| 窗口句柄无效 | 重新绑定 WeGame；客户端重建窗口后旧句柄可能失效 |
| WeGame 删除步骤被阻止 | 检查安装目录及所有配置的 Pak：原名文件必须不存在，对应 `.disabled` 文件必须存在 |
| 全局快捷键冲突 | 使用界面按钮，并检查其他程序是否占用快捷键 |
| 配置未生成或无法保存 | 检查目录写权限；创建失败时程序会使用内存默认配置并记录警告 |

遇到异常时，请先停止任务，结合日志检查实际界面和 Pak 状态，再决定是否继续。
